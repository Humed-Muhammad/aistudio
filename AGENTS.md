# Independent video workflow

For installation/onboarding requests, follow `docs/SETUP-AGENT.md` first. Do not run paid inference during setup. Distinguish a running UI from a generation-ready configuration.

Carry authorized jobs through preparation, quality review, generation and delivery without stopping after each processing stage. Ask only for missing creative choices or submission approval not already given. Never automatically purchase an HD upgrade: the user approves that step.

1. Preserve the source file and complete original audio.
2. Isolate vocals with Demucs, pitch +3 semitones with timing preserved, and embed them in the prepared composite. Do not attach separate audio to Seedance.
3. Generate depth with lucataco/depth-anything-video and retain its exact colors.
4. Obtain raw SAM 3 masks. If depth segmentation misses the subject or includes background, retry using original RGB detail and composite the original colored depth through those masks. Record this fallback.
5. Mandatory visual mask QA before EVERY generation: review the full clip, including all cuts, subject extremities, hair, hands, clothing, background spill, holes, alignment and flicker. Automated checks and sampled contact sheets alone do not establish full visual approval. Repair failures independently within the authorized task, then review again. Never approve a known-bad mask. Use mask_review to bind approval to current artifacts. User approval of the current mask may be recorded as such, without falsely claiming agent full-clip review.
6. Match the references and prompt to the actual subjects. A single Sirio replacement uses only Sirio's reference; never carry over the previous two-person mapping.
7. Show the exact creative prompt before submission. Existing explicit authorization to submit is sufficient; do not ask again unnecessarily. Submit through Enhancor as Seedance Edit draft by default.
8. Retrieve results and restore the entire untouched original source audio, discarding generated audio. Preserve draft artifacts. Report failures honestly; never claim submission or completion without an actual result.
9. On explicit approval, complete the draft at 1080p using draft_id and webhook_url, then restore original audio again.
10. Show the final preview and download. Keep status persisted and UI preview selection stable. Never expose credentials.

## Reference-mode routing (required)
Enhancor Edit accepts exactly one video: the prepared source. If the replacement identity reference is a video, use multi_reference (Omni), with prepared source @Video1 and identity reference @Video2. Use the identity clip for appearance only unless the user explicitly asks to use its voice or performance. Do not convert that reference to pictures without permission. For image references, default to Edit. Show the actual mode in the UI and saved generation metadata. Omni requires duration and aspect ratio; use the source framing and nearest supported duration. Preserve the full source audio in the final export and disclose any necessary short last-frame hold.


## Fast alternative: face mesh

Choose **Fast · Face mesh** in the UI, or use `workflow.py prepare VIDEO --mode face_mesh`. Install the optional worker once with `bash setup-face-mesh.sh` (Python 3.12 required; isolated `.venv-face`). The model downloads from Google's official storage on first use.

This path keeps the original video, tracks and saves facial landmarks, draws the mesh, isolates vocals and embeds the +3 pitched vocals. It makes **no depth or SAM calls**. It is currently designed for a single centered speaker; inspect all frames and stop on tracking gaps or incorrect face alignment. Do not claim mask review in this mode: review facial tracking and audio instead. Saved artifact hashes gate submission.

Use the same character references, draft-first submission, collection, original-audio restoration and explicitly approved HD upgrade. In the prompt, explain that mesh lines are motion guidance and must disappear, replace the complete original identity including hair, and preserve all dialogue and timing. Image reference uses Edit; video identity uses Omni. Keep advanced depth mode available. Do not submit automatically during setup.


### Combined depth + face mesh

Select **Advanced + Face mesh** in the UI or use `workflow.py prepare VIDEO --mode depth_mesh`. This runs the original depth/SAM pipeline, preserves its depth composite, then tracks the face from the original frames and overlays the mesh onto that composite. Landmarks are saved in `face-landmarks.json`. Review BOTH mask coverage and face tracking before approval. All artifacts, including depth, mask, mesh and embedded audio, are bound to review approval. Follow the same draft → approved HD → original-audio restoration flow.

For setup with all three preparation modes, also install Python 3.12 and run `bash setup-face-mesh.sh`. This creates an isolated mesh environment; the main app can retain its existing Python version. A Google Face Landmarker model is downloaded at first use. No SAM/depth inference is used by fast mode. Mesh modes are experimental and currently optimized for one centered speaker.


## Replicate provider (pay-per-use alternative)

`GENERATION_PROVIDER=replicate` (or no Enhancor key) submits to `bytedance/seedance-2.0` on Replicate with `REPLICATE_API_TOKEN` only; no webhook. Prompts cite `[Video1]`/`[Image1]`; image references → Edit, video identity → Omni (`reference_videos` = source + identity). Total reference video is limited to 15 s: refuse longer jobs rather than trimming silently. Drafts render at 480p with a saved seed. Replicate has no `draft_id`: an approved HD upgrade is a new, fully billed 1080p render of the same inputs and seed and may differ from the draft; say so before the user approves it. All review gates, draft-first submission and original-audio restoration apply unchanged.


## Real faces: Wan Animate Replace

Seedance on Replicate rejects photorealistic human faces (E005 "flagged as sensitive"); only Enhancor's `pass_faces` allows them. For real-person references, prepare with **Real faces · Wan Animate replace** (`--mode wan`). It normalizes the original video only: no depth, SAM or vocal isolation calls. Review the source clip (one clearly visible subject, no cuts) before approval; there is no mask to claim. Submission sends the original video plus ONE character photo to `wan-video/wan-2.2-animate-replace`; it takes no prompt, so say so instead of showing one. Video identity references and second characters are refused. Drafts render at 480 with a saved seed; the approved upgrade is a new, fully billed 720p render (Wan's maximum, not 1080p) that may differ from the draft. Original-audio restoration applies unchanged.


## Shorts editor (9:16 motion graphics)

A separate local workflow at `/shorts` (UI) or `shorts.py` (CLI). It adds captions, text pops, zoom punch-ins, shakes, flashes, sound effects, text behind the subject and images or emoji that follow a hand or the face. It makes **no generation calls**. Speech is only cut, never regenerated. When the whole recording is kept and noise removal is off, its original audio packets are copied unchanged. Sound effects are mixed on top. Install once with `make shorts`. Check with `doctor.py --shorts`.

1. `python shorts.py prepare VIDEO [--preset bold|boxed|minimal|none|auto]` transcribes the full recording and splits it into numbered parts. Several recordings uploaded together are kept in `parts/` and joined in natural file-name order into `upload.mp4` first (`shorts.join_recordings`; 30 fps, audio re-encoded once as AAC 256k and padded to each part's video length). With `ELEVENLABS_API_KEY` set it uses ElevenLabs Scribe (cloud, paid per minute, required for Amharic; the audio is sent to ElevenLabs), otherwise local whisper.cpp, which cannot transcribe Amharic. Each job has a spoken language (`language` in `workflow-mode.json`: am, en or auto; default am). Do not use auto for Amharic: Scribe can detect English and silently omit all Amharic words. A long gap between words is only removed as a pause when the audio is quiet, and `transcript-check.json` reports speech with no transcript; report it and re-transcribe instead of cutting. Steps can be cancelled (`POST /shorts/jobs/ID/cancel`). Recordings mix Amharic and English: never drop speech because of its language, and write on-screen text in the spoken language (Ethiopic script for Amharic).
2. Cut to what matters before anything else. `python shorts.py cut JOB` prints the parts. There is no target length: drop retakes (keep the best, usually the last complete take), false starts, repeated points, tangents and dead air; keep every distinct point, needed context and the payoff. When the user asks Claude Code to cut, write `{"keep":[ids in order],"removed":[{"id":3,"why":"retake"}],"summary":"…"}` and save it with `--file`. `--auto` calls the Claude API with the transcript text. `tighten` (default on) also removes filler words and pauses over `max_pause`. `--apply` builds `source.mp4`, cutting the original audio only at those points with short fades, then runs local MediaPipe hand, gesture, face and person-cutout tracking. Review the cut with sound and `tracking-preview.mp4`. Hand `left`/`right` means the side of the screen.
3. Follow `docs/shorts-style.md` (look, card templates, sound rules); the auto-planner receives it too. Captions default to `duo` (two-line glass, Noto Sans Ethiopic Black, line 2 in the accent; no black outlines, no yellow). Captions sit just under the speaker's chin by default (`caption_place` face: follows the face per phrase, never over the mouth, inside the safe zone 14–80% of the height clear of platform buttons); `fixed` uses `caption_y`. The creator picks style, font (`caption_font`), letters (`caption_fill`), motion, colour and position on the Captions tab with a live preview; once they do (`captions_auto` false) the planner keeps them. Fill `emphasis` for editorial and rise. Cards and text pops follow one **graphic style** per video (`graphics_style`: `glass` liquid glass, `bold` marker blocks, `editorial` serif accents, `minimal` no panels, `tech` dark grid + glow, `brutal` thick outline + hard shadow, `aurora` violet-coral gradient, `candy` pastel round, `noir` black + serif, `swiss` square caps, `clay` soft 3D; `motion/src/graphicKits.ts` sets fonts, type scale, surfaces, corners, accent treatment and scene backgrounds). The planner picks it unless the creator chose one (`graphics_auto` false, Graphics tab). Card headlines must not repeat the step or list text. `card` events (`template` steps|slider|stat|icons|list|chips|quote|title, `scene` overlay|dim|dark|light|split, `text` with `*accent*` words, `items`, `value`, `label`, `active`) carry structure. With `auto_sound` (default on) a sparse sound pass is added at render, levelled against the measured voice, from real recordings (the creator's `sfx-library/` first, else Remotion's hosted sounds cached in `models/sfx-cache/`; risers, hits and impacts only from the creator's pack); add `sfx` events only for extra moments. Back-to-back identical cards merge into one with a `timeline`; list rows appear when spoken. A `no_captions` event (`start`, `end`) hides the captions for words spoken in that window; add one only where the creator asks.
3. Plan graphics with `python shorts.py plan JOB` (prints the context: transcript, cuts, gestures, uploaded images). When the user asks Claude Code to plan, read that context and the keyframes, then write the plan JSON and save it with `--file`. `--auto` calls the Claude API (needs `ANTHROPIC_API_KEY`; it sends the transcript, 12 keyframes and uploaded images to Anthropic). Save only valid plans. Report every warning, such as a hand sticker scheduled where no hand is tracked.
4. Render a draft (`python shorts.py render JOB`, half resolution), inspect it, then render the final (`--final`). Rendering is local. If headless Chrome crashes, set `SHORTS_BROWSER` to an installed Chrome.
5. Never regenerate speech. Volume is levelled by default (`voice` in `workflow-mode.json`: `level` or `off`): at render, `voice-level.wav` is made from `source.mp4` with a slow speech rider (±8 dB), loudness normalisation to −14 LUFS and a peak limiter; gain only, `source.mp4` stays untouched, and sound effects are levelled against it. Apart from that, cutting is the only edit, except opt-in background-noise removal chosen per job (`noise` in `workflow-mode.json`): `light` = local highpass + RNNoise (model downloaded once to `models/`), `strong` = ElevenLabs Voice Isolator (cloud, paid; ask before choosing it for the user). The cleaned track is cached as `clean-<mode>.wav`, aligned to `upload.mp4`, used for transcription and the edit; `upload.mp4` stays untouched. Images the user uploads go in `runs/JOB/assets/` and are referenced by file name.
6. Screen recordings (B-roll) are uploaded next to images. `shorts.add_clip` converts each one to `assets/NAME.mp4` (H.264, 30 fps, muted), records it in `assets/clips.json` and saves 6 preview frames under `assets/.frames/NAME/`. A `broll` event (`asset`, `src_start`, `speed`, `layout` full|split|bubble|front, `corner`) shows it over the edit while the speaker's audio continues. Pick `src_start` from the preview frames so the screen matches the words. The plan check slows down or shortens clips that would run past the recording, skips overlaps, and falls back from `front` to `full` when no person cutout exists; report those warnings.
7. Hands-off is the default: the creator reviews, Claude edits. **Edit it for me** (upload checkbox, `POST /shorts/jobs/ID/auto`, or `python shorts.py auto JOB [--notes …]`) runs auto-cut → build + track → auto-plan (look + graphics) → draft render, as one cancellable step. It stops if `transcript-check.json` shows untranscribed speech instead of cutting it. Changes in words go through `POST /shorts/jobs/ID/revise` (`scope` graphics or edit); Claude receives the current plan and changes only what was asked. When the user asks Claude Code to edit a job, run `shorts.py auto` only after confirming it may spend their Anthropic key, or plan by hand with `--file`.
8. Background looks: the tracker cuts the person out with Robust Video Matting (ResNet-50 ONNX, ~107 MB in `models/`, 4 CPU threads; `SHORTS_MATTE=fast` uses the 15 MB MobileNet; MediaPipe is the fallback). `plan.background` places them on a look: `original`, `clean_blur`, `dark_glow`, `warm_studio`, `charcoal`, `cream`, `grid_paper`, `color_pop` and eight lit studio walls (`studio_blue`, `studio_coral`, `studio_teal`, `studio_violet`, `studio_rose`, `studio_forest`, `studio_slate`, `studio_sunset`) (`shorts.LOOKS`; no yellow), plus light (glow, rim, spotlight, vignette), subject (shadow, outline, scale) and **Pro finish**: `wrap` (match lighting: the wall colour wraps the cutout's edges and tints its shadows, an SVG filter), `reframe` (one steady chest-up punch-in from the median face, never exposing an edge; captions and LED tubes follow it), `tube` (LED light tubes on the wall), `grade` (contrast + wall-coloured soft-light tone) and `grain`. Studio walls ship with Pro finish on. A `look` event (`start`, `end`, `look`) switches to another look for part of the edit (e.g. `original` to show the real room), cross-faded over 8 frames; framing and grade stay. Add one only where the creator asks (Look tab: Switch look for a part). The planner picks `look` unless the creator chose one (`background.auto` false). Rebuilding the edit keeps the look.
9. The UI is a React + Vite app in `motion/studio/` (built to `static/studio/` by `make shorts` or `npm run studio:build`; dev server `npm run studio`). It plays the edit live with the Remotion Player using the same `motion/src` components as the renderer (`GET /shorts/jobs/ID/props`, media under `/runs/ID/` via `MediaBase`). Themes are token sets in `motion/studio/src/theme.ts`. The old page stays at `/shorts/classic`.


## Audio cleaner and transcriber

A separate local tool at `/cleaner` (UI) or `cleaner.py` (CLI): `python cleaner.py FILE [--noise light|strong|off] [--language am|en|auto] [--no-transcript]`. It takes any audio or video file, keeps an untouched copy as `input.*` in `runs/cleaner/JOB/`, and makes no generation calls. Noise removal reuses the shorts engines: `light` = local highpass + RNNoise, `strong` = ElevenLabs Voice Isolator (cloud, paid; ask before choosing it for the user). It writes `clean.wav` (aligned to the original, same length), `clean.mp3`, and for a video `clean-video.mp4` (picture packets copied unchanged, cleaned sound). Transcription runs on the cleaned sound when there is one: ElevenLabs Scribe with `ELEVENLABS_API_KEY` (cloud, paid per minute, required for Amharic), else local whisper.cpp, which refuses Amharic with a clear error. Outputs `transcript.txt`, `transcript.srt` and `transcript.json` (timed words). Same language rule as shorts: do not use auto for Amharic. Afaan Oromoo (`om`, Oromifa) is best effort: Scribe does not list it, so the cleaner asks for `orm` and, if refused, transcribes without a language hint; whisper.cpp refuses it. Oromo is recognised from the transcript words (`looks_oromo`, no model download), also under auto; `transcript.json` keeps the service's own guess in `reported`. Tell the user the Oromo transcript is unverified quality. Meta MMS (local, about 6 GB with PyTorch) is the stronger option: ask before installing it.


## Motion graphics (HyperFrames)

A separate local workflow at `/graphics` (UI) or `graphics.py` (CLI) for promos, explainers and ads written as code (HTML + GSAP) and rendered to MP4 on this Mac by HyperFrames. It makes **no generation calls** and draws only text, shapes, charts and the creator's own images. Install once with `make graphics`; check with `doctor.py --graphics`. Read `docs/motion-graphics.md` before writing or changing a composition, and use the installed `/hyperframes` and `/motion-graphics` skills for framework rules.

1. `python graphics.py new TITLE [--size portrait|square|landscape] [--image FILE …] [--music FILE]` creates `runs/graphics/JOB/` with the starter composition, the local motion kit (`kit/motion-kit.js`), GSAP, fonts and placeholders. Images go in `assets/` and fill the next empty `imageN` slot; a transparent product image sets `productFit` to `cutout`.
2. Plan first, using the 4-part brief in `brief.json`: who/where/how long, the look (hex colors, fonts, mood), scene by scene with seconds, and rules. The creator writes it, or `graphics.py draft JOB "request"` (UI: **Draft the brief**) has Claude Code draft it from their words and images with `[placeholders]` for anything not given; they edit and save it. Ask for missing parts; do not invent brand colors, prices or claims. `python graphics.py prompt JOB` prints the build prompt. `graphics.py build JOB --model …` (UI: **Build with Claude Code**) runs Claude Code headless on the creator's plan (API key removed), limited to the project folder and the graphics.py check/snapshot/content/draft-render commands; it backs up `index.html` to `history/` (`undo` steps back one build or change at a time). `graphics.py change JOB "…"` (UI: **Ask Claude for a change**) makes one targeted design change with the same limits, reviewing only the moments it touched (about a minute). Building and changing spend plan usage: only on the creator's click or request.
3. Write `index.html` with every word, price, color and image path in the content block (`data-composition-variables`). Animate images with `MotionKit` recipes or plain GSAP at absolute times; deterministic only. On-screen text goes in the creator's language (Ethiopic script for Amharic).
4. `python graphics.py check JOB`, then `snapshot JOB --at …` and **look at the frames**. Fix cropped or overflowing text, contrast, empty frames, missing images or fonts, and elements that pop on or off. Lint alone is not approval. Then `render JOB` (draft) and inspect the draft.
5. Show the draft. Render `--final` after the creator approves it. Content edits (`content JOB --set id=value` or the Content form) need no new Claude run; re-render a draft after each.
6. Keep everything local: do not run `hyperframes publish`, `cloud render`, `lambda`, `cloudrun`, `auth`, `tts`, music generation or feedback/telemetry reports, and do not install large optional models (TTS, MusicGen/ACE-Step, background removal) without asking. Always use `graphics.py` or set `HYPERFRAMES_NO_TELEMETRY=1`; pass `--no-clipboard` to `hyperframes add`. Never regenerate or alter the creator's voice; music or voice-over is one `<audio id="music">` clip.
